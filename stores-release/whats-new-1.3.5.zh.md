# MCPOrb Runner 1.3.5 更新内容

## 更智能的网关端口处理

统一 HTTP 网关在首选端口被占用时更加稳健。

- **自动回退** — 当配置端口（默认 5599）被占用时，应用会依次探测后续端口，并在 **HTTP** 标签页中以提示形式展示实际使用的端口，MCP 客户端可立即重连。
- **复用而非增生** — 反复启动应用不会每次都新建网关。Runner 会向 `127.0.0.1:<port>/mcp?token=<token>` 发送 `initialize` 探测，收到 HTTP 200 即复用已有网关，杜绝快速重启时的 `EADDRINUSE` 报错。
- **重启后状态准确** — 即使上次退出时网关被遗留，`unified_gateway_status` 也会通过 token 探测将其识别为 `running: true`，不再误报为已停止。

## macOS 沙盒稳定性修复（商店审核 2.4.5）

保存在沙盒容器之外（如用户通过选择器指定的 `~/Documents/MCPOrb`）的 Orb，在 Mac App Store 构建中现在可可靠启动。

- 当 `zip_path` 位于沙盒外时，网关通过 **stdin** 将 Orb ZIP 流式传输给 `mcporb-runtime` 子进程（`--orb-zip-stdin`，8 字节 little-endian 长度头）。子进程先读取 ZIP，再在同一管道上提供 MCP 服务，无需直接文件访问。
- 修复了因资料库移动或遗留网关导致的“读取 Orb ZIP 失败”问题。

## 资料库文件夹与设置的健壮性

- **设置位置**由沙盒容器内迁移至 `~/.mcporb/`，更新或容器重置后依然保留。
- **缺失检测** — 当所选资料库被移动、重命名或删除时，顶部横幅提供**一键重选**入口。`NSOpenPanel` 会预定位到原路径，旧的安全域书签会保留至你选定新位置。
- **正确合并** — `merge_settings` 在变更资料库路径时保留 `orb_library_bookmark`、网关 token 与引导状态，主题（浅色 / 深色 / 跟随系统）不再意外重置。
